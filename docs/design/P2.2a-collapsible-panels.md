# P2.2a — Collapsible side panels (Figma-style)

**Status:** done 2026-11-06 (D-41, `PROGRESS.md` → P2.2a); queued by the founder on 2026-11-06, after P14.5. Temporary panel icon (founder's choice); the optional resizing was built. The founder's spec below is verbatim; Claude's notes (checked 2026-11-06) follow it.

Do P2.2a — Collapsible side panels (Figma-style). This is a UI-only addition to the app shell (P2.2). Follow CLAUDE.md, DESIGN.md and the token system.

GOAL
The left and right side panels of the editor can be hidden and shown, so the canvas can use the full width — like Figma.

BEHAVIOUR
1. Two toggle buttons in the editor's top bar: one at the left end (controls the left panel), one at the right end (controls the right panel). Icons show the state (panel open / closed); use the Icon component — Phosphor `sidebar-simple` (mirrored for the right side) unless a better icon exists in the registry.
2. Keyboard shortcuts (check for conflicts with existing shortcuts first and tell me if any clash):
   - Ctrl/⌘ + \  → hide/show BOTH side panels (focus mode)
   - Ctrl/⌘ + Alt/Option + [  → toggle left panel
   - Ctrl/⌘ + Alt/Option + ]  → toggle right panel
   Also add these three as commands in the ⌘K command palette.
3. When a panel is hidden it takes zero width and the canvas grows into the space. The drawing must NOT jump on screen: adjust the canvas pan so the plan stays exactly where it was visually.
4. Show/hide animates in ~200 ms using motion tokens; no animation when the user prefers reduced motion.
5. Hidden panels stay hidden until the user opens them again — never auto-open (e.g. on selection). While a panel is hidden, show a small always-visible edge tab (at least 24×24 px, not hover-only) on that side of the canvas that reopens it.
6. If the panel being hidden contains keyboard focus, move focus to its toggle button.
7. Remember the open/closed state per user across reloads (store it as a user preference, not in the plan document).
8. Narrow windows (below the compact-layout breakpoint): panels open as overlays on top of the canvas and close with Esc or a click outside.
9. The chat panel: if it is separate from the side panels, include it in focus mode (Ctrl/⌘ + \) and give it its own toggle the same way.

RULES
- This is view state, not a plan change: it does not go into undo/redo, changesets or the engine. Keep it in /frontend only.
- Panel widths, edge-tab size, animation and colours come from tokens (add `size.panel.left`, `size.panel.right` if missing). No raw values.
- Accessibility: toggle buttons have aria-label ("Hide left panel" / "Show left panel"), aria-expanded and aria-controls; tooltips include the shortcut; focus ring visible.

OPTIONAL (do only if quick, otherwise list as a follow-up): resize panels by dragging their inner edge, with min/max widths from tokens, double-click to reset, and arrow keys on the focused edge for keyboard resizing; remember the width.

TESTS
- Unit: panel-state store (toggle, focus mode, persistence).
- Browser test: click toggles, all three shortcuts, edge tab reopens, state survives reload, drawing position unchanged after hide/show, focus moves correctly, reduced-motion has no animation.

ACCEPTANCE
✅ Both panels hide/show by button, shortcut, command palette and edge tab; the canvas fills the space without the drawing shifting; state persists after reload; works in dark and light themes.
After finishing: run the plancraft-ux-refine skill quick pass on the changed components (if the skill is installed), update PROGRESS.md, and explain the result to me in plain language.

## Claude's notes (2026-11-06, before building)

**Shortcut check (asked for in item 2).**
- No clash inside the app: the editor's single-key shortcuts (V W R D N S M T, + − 0, arrows, Esc, Space) and the Vault's (⌘K, ⌘A, N, ⇧N, F2, Del, ↵) ignore key presses combined with Ctrl/⌘/Alt (except ⌘K and ⌘A in the Vault).
- No clash with Chrome, Safari or Firefox: ⌘\ / Ctrl+\ and ⌘⌥[ / ⌘⌥] are unused there (Figma uses ⌘\ for the same purpose).
- **Watch out:** on Windows/Linux with many non-US keyboard layouts (e.g. German), Ctrl+Alt is AltGr, which types `[` and `]`. Match the shortcut on the physical key (`event.code` `BracketLeft` / `BracketRight`), ignore it while typing in text fields, and test with a non-US layout.

**What exists today (P2.2).** The left panel already opens and closes from the panel rail (Rooms / Layers / Library); the right panel has a close button and re-opens from the Issues bell; the chat is a separate column toggled from the top bar; below 1100 px all three already open as overlays, one at a time, closing on narrow resize. P2.2a moves the toggles into the top bar, adds focus mode, edge tabs, animation, persistence, Esc / click-outside for the overlays, and keeps the drawing still.

- **⌘K in the editor:** today the command palette exists only in the Vault. P2.2a needs one in the editor (or a shared palette): plan for it in this prompt.
- **Tokens:** the formal token system (skill §3) is not built yet; the docs session made an as-built index only. Until the founder approves the migration, add the panel sizes and the 200 ms motion value as CSS variables in `frontend/src/design/tokens.css` (owned by the design-system session: coordinate through `SESSIONS.md`).
- **"Drawing doesn't move":** the canvas keeps its view as a centre point plus scale; when the canvas edge moves by *w* px, shift the centre by *w / 2 / scale* so the plan stays put (and during the 200 ms animation, every frame).

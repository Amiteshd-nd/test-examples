# Plan schema changelog

Every change to the stored Plan format: version, date, what changed, the migration from the previous version, and the test that proves old files still load (PRD §0.4 rule 4).

| Version | Date | Change | Migration |
|---|---|---|---|
| Plan graph 1 (P3.3) | 2026-11-07 | D-51: `PlanGraph` (`nodes`: `GraphNode` with `id`, `level`, `type`, `name`, `area_m2`, `at`, `zone` front / middle / rear, `exterior`, `exterior_sides`, `entrance`, `vastu_zone`; `edges`: `GraphEdge` with `a`, `b`, `kind` open / door / wall / adjacent, `via`; `provenance`). JSON Schema `plan-graph` added. Derived from plans, never stored: the plan format stays 1.3.0. | None (first version). Tested in `graph/plan-graph.test.ts`. |
| Issue (P3.2) | 2026-11-07 | D-49: `Issue` gains optional `fix` (`IssueFix`: `label`, `steps` = command calls `{id, params}`), a quick fix the host runs as one batch. JSON Schema `issue` regenerated. Issues are results, not stored in plans: the plan format stays 1.3.0. | None (optional field; older readers ignore it). Tested in `rules/check.test.ts`. |
| 1.3.0 | 2026-11-06 | P3.1 review (D-46): the plot may record `road_width_cm` (optional, cm), the width of the road in front: bylaws such as BBMP's FAR depend on it. Rule tables may go `by: road_width_m`. JSON Schemas `plan`, `rule`, `rule-pack` regenerated. | `1.2.0 → 1.3.0` in `engine/schema/migrations.ts` changes nothing (older plans don't record road width). Tested in `schema/migrate.test.ts`; samples in `engine/samples/1.3.0/`; older samples still load. |
| Rule pack 1 | 2026-11-06 | P3.1 (D-45): `RulePack` (`format: "plancraft-rule-pack"`, `version: 1`, `id`, `name`, `description`, `applies` always / vastu, `rules`). `Rule` gains `label`, `note`, a `table` (`by` plot_area_m2 / plot_width_m / plot_depth_m, rising `rows` of `upto` and `value`), `zones` (Vastu), scope `room_types`, `door`, `side`; `check` is one of eleven names; unit `zone` added. `Issue` gains optional `verified`. JSON Schema `rule-pack` added, `rule` and `issue` regenerated. Separate from the plan format. | None (first version). Packs in `engine/rules/packs/`, checked by `rules/check.test.ts`. |
| 1.2.0 | 2026-11-06 | P2.5 (D-44): each level gains four annotation maps: `lines` (`id`, `points` ≥ 2, `closed`), `dimensions` (`id`, `start`, `end`, `offset`: the dimension line's distance to the left of start → end), `texts` (`id`, `at`, `text` 1–500 characters, `size` text height in cm, `rotation_deg`) and `hatches` (`id`, `polygon`, `pattern` diagonal / cross / dots / solid), all with optional provenance. They don't take part in rooms, areas or checks. JSON Schema `plan` regenerated. | `1.1.0 → 1.2.0` in `engine/schema/migrations.ts`: every level gets the four maps, empty. Tested in `schema/migrate.test.ts`; the 1.0.0 and 1.1.0 samples still load (`samples/samples.test.ts`); samples in `engine/samples/1.2.0/`. |
| Vault index 2 | 2026-11-06 | P14.4 (D-39): each file gains `active_ms`, its editing time since the last version (A2 M12: an unnamed version every 30 min of editing). Versions now keep a copy of the plan at `versions/<file-id>/<version-id>.json` beside the list `versions/<file-id>.json`. JSON Schema `vault-index` regenerated. | `1 → 2` in `migrateVaultIndex`: every file starts at `active_ms: 0`. Tested in `vault/vault.test.ts`; the local demo vault upgraded itself on its first save. |
| Vault index 1 · Package 1 | 2026-11-06 | P14.2 (D-36, D-37): `data/vault/index.json` (`VaultIndex`, `format: "plancraft-vault"`, `version: 1`): workspace, folders (parent, colour, style, order, star, archive, trash) and files (kind, status, owner, last editor, size, `doc_rev`, `thumbnail_rev`, summary) in id-keyed maps; plans at `docs/<id>.json`, thumbnails at `thumbs/<id>.svg`. `.plancraft` package (A2 M10): a zip of `manifest.json` (`PackageManifest`, `version: 1`), `document.json`, `thumbnail.svg`, `versions.json`. JSON Schemas `vault-index` and `plancraft-package-manifest`. Separate from the plan format. | None (first versions). `migrateVaultIndex` refuses newer formats with a reason; plans inside a vault or package are upgraded by `loadPlan` (tested with a 1.0.0 plan in `vault/vault.test.ts`). |
| Library index 1 | 2026-11-06 | `data/library/index.json` (`LibraryIndex`, `version: 1`): entries with id, name, source, status, imported_at, reviewed and `PlanTags` (P1.4). Separate from the plan format. | None (first version). |
| 1.1.0 | 2026-11-06 | A2 amendments M1 + M3 (D-29): `levels` and each level's `walls`, `rooms`, `openings`, `stairs`, `columns`, `fixtures` are id-keyed maps (key = object `id`); levels gain `order` (fractional index); new per-level `separators` map (`id`, `start`, `end`). | `1.0.0 → 1.1.0` in `engine/schema/migrations.ts`: lists become maps in the same order, levels get increasing `order` keys, `separators` start empty; refuses plans that reuse an id. Tested in `schema/migrate.test.ts`; 1.0.0 samples still load (`samples/samples.test.ts`). |
| 1.0.0 | 2026-11-06 | First format (P1.1, D-11…D-14): plan meta, plot, setbacks, levels with walls (external/internal/parapet/compound), rooms (25 types, seed, behaviour, size range, loft), openings (door/window/ventilator/opening, chajja), stairs, columns, fixtures; per-object provenance. JSON Schema in `engine/schema/json/`. | None (first version). Samples in `engine/samples/1.0.0/`. |

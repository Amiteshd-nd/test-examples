# Integration guide (engine)

How another editor adopts the PlanCraft engine. Kept current at the end of every phase (PRD §0.4 rule 6); completed in P10.6.

## Status
Phases 1, 2 and 14 done (updated at the end of Phase 2, 2026-11-06). Available from `@plancraft/engine`:
- **Formats** (zod schemas + TypeScript types): `Plan` and its parts, `Rule`, `Issue`, `Brief`. JSON Schema files for non-TypeScript hosts: `engine/schema/json/*.schema.json`.
- **`loadPlan(json)`**: migrates an older file to `CURRENT_SCHEMA_VERSION` and checks it against the schema.
- **`validatePlan(json)`**: `loadPlan` + geometry checks; returns `{ok, plan, issues, rooms}`. `ok` is false only when there is an error (warnings allowed). Rule ids: `VALIDATOR_RULES`.
- **`deriveRooms(level)`**: each room's clear floor outline (cm), holes, area (m²) and bounding walls.
- **`wallOutlinesCm(level, {solid})`**: every wall of a level as joined outlines in cm (no seams at corners or junctions), openings cut out unless `solid`; outer outlines anticlockwise, holes clockwise. For drawing walls in a host's canvas.
- **Canvas helpers (P2.3):** `planDrawing(plan, rooms)` returns everything a plan view draws, in cm with y north (walls, `wallShapes`, opening symbols with lines and anticlockwise arcs, columns, stair treads, rooms with label points and areas, `bounds`). `buildPlanIndex(level, drawing)` indexes it in R-trees; `hitTest(index, point, toleranceCm)` returns the `{kind, id}` under a point (opening > column > wall > separator > stair > room); `snapPoint(index, point, {tolerance, snaps, grid, from})` returns where the cursor lands and what it snapped to. Turn pixel tolerances into cm by dividing by your pixels per cm. `gridPlan({cols, rows})` makes a regular test plan.

- **`importDxf(bytes, {name, mapping, units})`**: reads a DXF (ASCII or binary) into a plan plus a conversion report (found / guessed / failed / notes, with provenance on every guessed value) and the source lines for a preview. `DEFAULT_IMPORT_MAPPING` / `ImportMapping` describe which layers, blocks and labels mean what. `reportToMarkdown(report)` formats the report.
- **`renderPlanSvg(plan, {rooms, underlay, title})`**: an SVG preview string.
- **`exportDxf(plan, {layers})`**: `{ok, dxf, check}`: an AutoCAD 2000 DXF (text, millimetres) on the layers of `DEFAULT_EXPORT_LAYERS`. `ok` is false when reading the file back lost something (`check.mismatches` says what); hosts must not offer such a file for download. Encode the text as UTF-8/ASCII to save it (it is pure ASCII).

- **Plan Library**: implement `DocumentStore` (`loadPlan`, `savePlan`, `listPlans`, `loadIndex`, `saveIndex`; all async) for your storage, or use `MemoryStore`. `addToLibrary(store, {id, plan, status, now, source})` saves and tags a plan (`autoTag` gives `PlanTags` with provenance); `tagReviewCsv(index)` / `applyTagReview(store, csv)` run the human review. The engine never reads the clock: pass `now`.

- **Vault (P14.2):** `new Vault({storage, ids, clock, user, workspace})` gives folders and files with `listFolder`, `tree`, `recent`, `search(query, filters)`, `listTrash`, `createFolder`, `createFile`, `loadDocument`, `saveDocument`, `rename`, `move`, `duplicate`, `setStar`, `setColor`, `setStatus`, `archive`, `trash`, `restore`, `deleteForever`, `purgeTrash(days)`, `getThumbnail` (SVG), `listVersions`, `exportPackage` / `importPackage` (`.plancraft`). Supply `storage` (a `VaultStorage`: read / write / remove text by key; `MemoryStorage` for tests), `ids` (an `IdSource`; `formatUlid(Date.now(), randomBytes)` makes ULIDs) and `clock` (a `Clock` returning ISO time). Failures that a user can fix throw `VaultError` with a plain sentence. `blankPlan({name})` makes a new empty plan. Formats: `VaultIndex`, `PackageManifest` (JSON Schemas `vault-index`, `plancraft-package-manifest`).
- **Saving and versions (P14.4):** `saveDocument(id, plan, {baseRev})` refuses with `VaultConflictError` when the file was saved since `baseRev` (pass the revision your copy came from; hosts with several tabs or users should always do this). Each save adds editing time (`active_ms`; pauses count at most `IDLE_CAP_MS`); after `AUTO_VERSION_MS` (30 min) the save also makes an unnamed version. `createVersion(id, label)` makes a named one; `listVersions(id)` and `loadVersion(id, versionId)` read them. Moving or restoring a file does not change its edit time.
- **Views outside a folder (P14.5):** `folderSummaries(ids)` gives counts, size and paper previews for folders shown in Search, Starred or Trash (a folder in Trash counts what went with it). `purgeTrash(days = 30)` deletes for ever what has been in Trash longer; call it when your Vault view opens (the browser app does, once per visit).

- **Commands (P2.4, P2.5): the only way to change a plan.** `PLAN_COMMANDS` lists them by id, each with `label`, `description`, a zod `params` schema, `aliases` and its typed form (`text`): MOVE, DELETE, ADD_WALL, ADD_ROOM, ADD_OPENING, SET, ADD_LINE, RECTANGLE, ROOM, ADD_SEPARATOR, ADD_STAIR, ADD_DIMENSION, ADD_TEXT, ADD_HATCH, COPY, ROTATE, MIRROR, OFFSET, TRIM, EXTEND, SET_LENGTH. Keep a `History` (`createHistory(plan)`) and call `execute(history, request)` with the PRD §4.4 request: `{op: 'execute', id, params}` or `{op: 'batch', steps: [{id, params}]}` (all or nothing), plus optional `revision` (fails with `stale` if the plan moved on), `request_id` (a retry returns the first outcome), `author`, `ts`, `gesture` (steps with the same gesture merge into one undo step). It returns `{history, outcome}`; `outcome.ok` false carries a `code` and a plain-language `message` (shown to the user as is). `preview(history, request)` gives the result without recording it (for drags and tool previews). `undo(history, author)` / `redo(history, author)` are per author and report `skipped` patches that someone else changed since. `applyRemote(history, changeset)` takes another user's change without making it undoable here. New object ids go **in the params** (`id`), from your `IdSource`: commands never invent ids or read the clock (A2 M2), so the same request always gives the same plan.
- **Typed commands:** `parseCommand('MOVE W3 0,0 100,0', {ids})` → `{ok, call}` (aliases such as `M`, `name=value` pairs, quoted text, lists of points); `formatCommand(call)` writes one back; `findCommand(word)` and `usage(command)` for help text. Every command gives the same plan called directly, typed, or sent as a JSON tool call (`engine/commands/three-ways.test.ts`).
- **Precision input (A2 M5):** `parseLength('15\'6"')` → cm (`450`, `4.5m`, `4500mm`, `15'`, `6"`); `typedPoint(text, {last, toward})` reads `450` (along the cursor's direction), `450<90`, `@dx,dy` and `x,y` into a point.
- **Changesets (A2 M9):** `diff(a, b)` → patches (`{path, before, after}`; records walked field by field, arrays single values), `apply(doc, patches)`, `applyChecked(doc, patches)` (skips patches whose value changed since), `invert(patches)`, `changedObjects(patches)` (which objects changed: dirty flags for incremental redraws, A2 M6). `merge3` arrives with P15.3.
- **Annotations (P2.5):** `planDrawing` also returns `lines`, `dimensions` (with extension lines, ticks, text spot, readable angle and the measured length in cm: format it in your units), `texts` (with their pick box) and `hatches` (pattern `diagonal` / `cross` / `dots` / `solid`). `hitTestAll(index, point, tol)` lists every object under a point, top first, so a host can step through overlapping ones.

Format **1.2.0**: objects are maps keyed by id (`plan.levels.L0.walls.W1`); use `values(map)`, `levelsInOrder(plan)` / `firstLevel(plan)` and `orderBetween(a, b)` from the engine rather than relying on key order. Separators (`level.separators`) bound rooms like zero-thickness walls. Annotations (`lines`, `dimensions`, `texts`, `hatches`) are drawn and stored but don't affect rooms, areas or checks; the DXF export doesn't write them yet (P7).

Units: all lengths in cm on a 0.1 cm grid, coordinates within ±1 km; areas in m² to 0.01.

## Rules for hosts
- Import only from `@plancraft/engine` (its `index.ts`). Anything not exported there is internal and may change.
- The engine never touches the DOM, network, storage or files. The host supplies those through the plug-in interfaces (PRD §3.4: `DocumentStore`, `AuthContext`, `FileIO`, `ModelProvider`, `Clock`, `IdSource`), which arrive with the phases that need them.
